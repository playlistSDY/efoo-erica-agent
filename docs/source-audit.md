# 한양 ERICA 복지포털 공개 페이지 수집 범위 감사

2026년 11월 13일 19시 30분 KST에 보존한 네 식당의 `source.html`과 `normalized.json`을 읽어 초기 수집 범위를 점검했다. 공유 CSS 11개와 외부 JS 2개도 공개 URL에서 읽어 모두 HTTP 200을 확인했다. 이 기록은 **확장 구현 전 원본 스냅샷의 필드 목록**이다. 로그인·구매·OpenAI 호출은 수행하지 않았다.

초기 수집기는 요청 당일 메뉴 10개와 메뉴 이미지 URL 9개를 정규화했지만 식당 기본정보, 공지, 대표사진, 주간 메뉴, 구매 상태, 공통 UI와 정적 자산을 구조화하지 않았다. 원문 HTML 안에는 이 정보가 이미 남아 있으나, 별도 파일을 가리키는 URL만으로는 이미지·CSS·JS의 바이너리가 보존되지 않는다. 확장 수집에서는 관련성에 관계없이 발견한 필드와 자산을 아카이브하고, **아카이브 보관과 답변용 색인 선택을 분리**한다.

언어별 원문도 서로 다를 수 있다. 예를 들어 홈 학생식당 한국어 중식은 11:30~13:30이지만 `operating_time_en`에는 11:30~12:30이 있었다. 원문 언어와 값을 모두 남기고 한국어 질의에는 한국어 원문을 우선하며 불일치 자체를 숨기지 않는다.

일반 매장 예시 바르바꽃집(id 23)은 생활서비스, ERICA컨벤션센터 1F, 건물 307, 연락처 010-8847-2507, 영업시간 08:00~18:30, 운영 공지 “커피와 꽃이 함께하는, 마음을 전하는 공간입니다.”를 표시한다. 대표사진 1개 외에 상세 HTML 안에 alt 없는 PNG 3개가 있다. 이 이미지들의 텍스트 내용은 HTML `get_text`로 읽을 수 없다. 이미지 바이너리와 출처를 보관하되 별도의 OCR/이미지 분석을 하지 않았다면 이미지 안의 메뉴·가격을 읽었다고 주장하지 않는다.

현재 공개 공지는 id 13 “창의관식당 천원의 아침밥 결제 방식 변경 안내”다. 2026-11-02 게시, 작성자 운영 관리자, 일반 공지이며, 11월 2~6일 온라인·오프라인 병행, 11월 9일부터 온라인 구매만 가능하고 오프라인 키오스크 결제 불가라는 본문을 갖는다. 공지의 날짜 범위를 유지하여 과거 기간을 현재 정책으로 합치지 않는다.

식권 판매처 페이지는 HTTP 200으로 로그인 없이 열리며 “원하시는 식당을 선택하여 식권을 구매해 주세요.”라는 안내와 창의인재원식당·창의관 1층 한 항목을 제공한다. 항목 링크는 `/theme/pages/facilities/detail.php?id=4`다. 이 페이지에는 embedded DB 배열이나 입력 폼이 없었다.

공개 홈과 공통 내비게이션에서 별도 조직소개·대학연혁·학과소개·FAQ 페이지 링크는 발견하지 못했다. `/robots.txt`와 `/sitemap.xml`은 404였다. 이는 사이트 전체에 그런 문서가 절대 없다는 증거가 아니며, 이번에 관찰한 공개 경로의 범위다. **현재 근거로 학교생활의 복지시설·학식·공지는 안내할 수 있지만 학교 전체 학사·입학·졸업·연혁 지식을 확보했다고 표현하면 안 된다.** 이런 질문에는 미확보 범위를 안내하거나 별도 공식 출처를 추가해야 한다.

## 이미지와 주간 정보 수량

수량은 DOM의 `img` 기준이다. 대표사진은 각 1개이고 별도 사진 갤러리·캐러셀·`srcset`·`data-src`는 이 네 스냅샷에서 발견되지 않았다. 주간표는 텍스트 표시이며 사진은 선택된 당일 카드에만 있다.

| 식당 | 대표사진 | 실제 당일 메뉴 사진 | 그 밖의 이미지 | 전체 img | 당일 메뉴 카드 | 주간 메뉴 PC / 모바일 |
| --- | ---: | ---: | --- | ---: | ---: | ---: |
| 교직원식당 | 1 | 2 | HY-SQUARE 로고 1 | 4 | 2 | 10 / 10 |
| 학생식당 | 1 | 3 | HY-SQUARE 로고 1 | 5 | 3 | 15 / 15 |
| 창의인재원식당 | 1 | 3 | HY-SQUARE 로고 1 | 5 | 3 | 25 / 25 |
| 창업보육센터식당 | 1 | 1 | HY-SQUARE 로고 1 + 석식 사진 대체 HYU 로고 1 | 4 | 2 | 10 / 10 |

네 페이지의 이미지 태그는 합계 18개, 직접 이미지 URL은 중복을 제거하면 15개다. 그중 시설 사진 4개·실제 당일 음식 사진 9개·공통 로고 2종이다. 현재 창업보육센터 석식에는 음식 사진이 없다.

모든 주간표의 날짜 범위는 **2026-11-08부터 2026-11-14까지**이며, 일별 탭의 `selectDay`에 ISO 날짜가 있다. PC·모바일 표시는 같은 메뉴의 중복 표현이므로 합산하지 않는다. 네 식당을 합치면 주간 60개 카드이며 당일 10개는 이 집합의 일부다. 주간 이동 버튼은 `goToWeek('2026-11-06')`, 현재 `2026-11-13`, 다음 `2026-11-20`을 제공한다. 메뉴가 빈 칸의 `—`는 휴무 확정 정보가 아니다.

창의인재원 주간 아침 메뉴 7개에는 구매 상태가 표시된다. PC 기준 `품절` 2개와 `판매 종료` 5개이고 모바일에 같은 7개가 반복된다. 선택 당일 유부초밥의 일별 카드에도 `판매 종료`가 있다. 실제 현시점 상태와 혼동하지 않도록 메뉴 날짜와 수집 시각에 묶어 보관한다.

## 공통 UI와 정적 자산

네 페이지는 다음 공통 구조를 갖는다. 공통 텍스트와 구현 자산도 사용자의 전체 수집 범위에 포함한다.

| 항목 | 스냅샷 확인 결과 |
| --- | --- |
| 내비게이션 링크 | `a[href]` 19개, 고유 href 9개. 홈·시설안내·식권구매·공지사항·마이페이지·로그인·언어별 상세 페이지 |
| 언어 전환 | 한국어·영어·중국어 링크가 상단과 사이드바에 반복되고 head에 `rel=alternate` 3개 있음 |
| 내부·외부 링크 | HTML의 직접 anchor는 모두 동일 사이트 상대 경로. 외부 사이트 anchor·전화 tel·메일 mailto는 발견되지 않음 |
| 로그인 UI | 로그아웃 상태의 “로그인이 필요합니다”, LOG-IN 링크와 모바일 사이드바 토글. 식당 정보와 식단은 비로그인 HTML에 이미 포함됨 |
| 입력 폼 | 이 상세 HTML 안에는 form·input·select·textarea 요소가 없음. 날짜/보기 변경은 button onclick으로 처리 |
| 푸터 | 실제 표시 `© 2026 Hanyang University All rights reserved.`. 주석 처리된 주소·가상 전화 `031-000-0000`·메일 예시는 실제 식당 연락처로 색인하지 않음 |
| 메타데이터 | `html lang=ko`, UTF-8, viewport 메타 2개. title·description·OpenGraph 메타는 이 HTML에서 없음 |
| 외부 JS | `/theme/assets/js/base.js`, `/theme/assets/js/mock-data.js?v=1794565825` 두 파일. `MOCK` 표시를 실제 식단 데이터와 구분 |
| Inline JS | 3개. 언어 전환/사이드바, PHP 렌더 완료 플래그, weekly/daily 보기·날짜 이동 등. 코드 원문 보관 |
| CSS | link stylesheet 11개와 inline style 블록 1개. 개별 요소의 style 속성도 원문에 포함 |
| 주석 | 페이지별 HTML 주석 29개. 레이아웃·MOCK·비표시 푸터 등 원문 보관 |

직접 CSS 파일은 `reset.css`, `tokens.css`, `typography.css`, `layout.css`, `components/button.css`, `card.css`, `badge.css`, `form.css`, `nav.css`, `lang-switcher.css`, `pages/facilities/detail.css`이다. 모두 `https://life.hanyang.ac.kr/theme/assets/css/` 아래에 있다. 두 JS와 11 CSS는 감사 시 HTTP 200이었다.

`typography.css`는 다음 외부 CSS 3개를 `@import`한다. 정보 보존 범위에는 이 외부 CSS와 그 안의 폰트 참조도 의존 자산 manifest로 기록한다. 이번 요청은 사이트 배포 미러가 아니므로 외부 폰트 전체를 재귀 다운로드하지 않는다. 이번 감사 역시 외부 폰트 파일의 전체 다운로드와 수량 검증까지 수행하지 않았다. 미보관·실패·정책 제한은 manifest에 남겨 완전한 오프라인 복원이 검증되었다고 과장하지 않는다.

- `https://fonts.googleapis.com/css2?family=Noto+Sans+KR:wght@100..900&display=swap`
- `https://fonts.googleapis.com/css2?family=Material+Symbols+Sharp:opsz,wght,FILL,GRAD@20..48,100..700,0,0&display=swap`
- `https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard-dynamic-subset.min.css`

`form.css`에는 `data:image/svg+xml` 내장 그림이 있으며, 원문 CSS를 보관하면 이 데이터도 남는다. 공통 링크 대상의 로그인·구매·마이페이지로 이동하여 개인 데이터나 거래를 수집하는 작업은 이 공개 상세 페이지 아카이브에 포함하지 않는다. 링크의 존재와 속성은 전부 보존한다.

## 원본과 해석의 경계

알레르기, 칼로리, 재료별 영양값, 혼잡도는 이 네 페이지에 확인 가능한 전용 필드로 제시되지 않는다. 메뉴명·사진·“건강한 한 끼” 같은 홍보 문구로 값을 만들어 채우지 않는다. 영업시간과 수집 당시 판매 상태처럼 실제 표시된 정보는 출처와 시각을 붙여 답변할 수 있다.

초기 정규화 JSON의 키는 `code`, `name`, `date`, `source_url`, `fetched_at`, `meals`뿐이었다. 이후 확장 수집의 성공 여부는 이 목록과 대조하여 필드별 구조화 값, HTML, 자산 manifest 및 실제 저장 파일까지 확인해야 한다. 문서 전체 수집은 임베딩 문맥에 공통 UI·스크립트를 무조건 넣는다는 뜻이 아니다. 모든 원본은 남기고, 질문에는 관련 식당·날짜의 검증 가능한 근거를 선택한다.


## 확장 수집 구현 반영 현황

위의 누락 표는 최초 식단 전용 수집기를 감사한 기록이다. 이후 확장 수집은 공개 시설 상세 48곳(구내식당 detail 4곳과 일반 shop-detail 44곳), 11월 8~14일 식단 스냅샷 28건의 메뉴 60개, 공지 1건, 홈·시설 목록·식권 판매처 안내 3건, 홈의 공개 구매 관측 1건을 확보했다. 원본 출처 81건이며 본문·기본정보·공지·시간 조건·상세 HTML·이미지 참조·공개 JSON의 모든 필드를 보관한다.

일별 식단 페이지를 추가 확인한 뒤 JPEG·PNG 캐시 115개(26,556,687바이트)를 보관했다. 60개 메뉴에 연결된 서로 다른 음식 사진은 48개다. 답변 본문에서 실제 인용한 근거에 사진이 있으면 요청 여부와 관계없이 최대 6개 자동 표시한다. 11월 14일 창의인재원 중식·석식처럼 공식 일별 페이지에 사진이 없는 메뉴에는 다른 날짜의 사진을 대신 붙이지 않는다. CSS·JS·로고·외부 폰트 등의 비다운로드 참조는 manifest에 남기며, 사이트 오프라인 미러나 이미지 속 텍스트의 OCR·Vision 검색을 구현한 것은 아니다. 공개 필드의 재고·결제 표시는 관측 시점의 원문이며 실제 구매를 수행하지 않는다.

## 11월14일 기간 조회와 자동 갱신 추가 확인

요청한 날짜·식당의 누락 또는 유효시간 만료를 확인한 뒤 공식 일별 페이지를 다시 방문하고 성공한 스냅샷만 교체한다. 임베딩은 해당 범위의 바뀐 메뉴 청크에 한정한다. 정기 수집은 오늘부터14일을 기본 범위로60분마다 확인한다. 공식 페이지에 메뉴가 없다는 확인과 페이지 확인 실패를 서로 다른 상태로 보관하며, 갱신 실패 대상의 예전 메뉴를 최신 답변 근거로 사용하지 않는다.

검증 시점 자료는4개 식당의11월8~27일80개와 학생식당11월28~30일3개를 합친83개 스냅샷, 메뉴122개, 시설·공지·일반 안내·공개 관찰53개로 총136개 출처다. 이미지 파일115개는 그대로이며 전체471개 청크가 임베딩됐다. 11월28~30일은 모든 식당을 수집한 범위가 아니라 커스텀 질문에서 선택한 학생식당 범위다. 수집량은 이후 질문과 정기 실행에 따라 바뀐다.

답변용 텍스트는 menu·profile·notice·page로 나누고 시설·날짜·문서 종류를 구분하여 검색한다. 학교생활 서비스와 시설 종류의 전체 소개 질문은 홈·시설 목록 등 일반 안내 page를 검색하며, 특정 시설의 기본정보·공지 질문처럼 양수 유사도 후보를 유지한다. 일반 검색과 순수 메뉴 질문은 기본 임계값 0.30을 적용한다. 실제 OpenAI 호출에서 메뉴·가격, 우편 취급 시설의 위치·시간, 영업 종료와 배식 마감의 차이, 결제 공지, 사진 응답과 근거 없는 질문의 거절을 제한된 사례로 확인했다. 이 결과는 모든 시설·질문의 정확도 보장을 뜻하지 않는다. AWS·RDS·S3 배포와 운영 연동은 아직 별도 검증 대상이다.
