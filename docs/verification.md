실제 API와 수집 원문을 대조한 사례는 다음과 같다.

- 우체국 질문을 공식 명칭인 안산 한양대 우편 취급국으로 연결하고 학생복지관1층, 건물번호102, 09:00~18:00, 점심시간12:00~13:00, 공개 연락처를 확인했다.
- 창업보육센터식당의 석식17:00~19:00와 배식대18:30마감을 구분했다.
- 창의관식당 천원의 아침밥 공지에서 11월9일부터 온라인 구매만 가능하고 키오스크 결제가 불가함을 안내했다.
- 바르바꽃집 공개 사진4건을 인용 자료에서 선택했고 웹에서는 우편 취급국 사진의 실제 로드와 출처를 확인했다.
- 전체 시설 소개는 공식 목록의48곳과7개 분류를 근거로 검색한다.
- 수집 범위에 없는 졸업요건 질문과 메뉴 없는 날짜는 근거 부족으로 안내했다.
- 기존 학생식당 메뉴·가격, 6천원이하 비교와 후속 질문도 실제 API에서 확인했다.

새 수집 범위에 맞게 자료 종류를 메뉴·시설·공지·일반 안내로 분리했다. 시설의 확인된 별칭, 전체 시설 목록 질의, 동일한 이름의 여러 지점과 공동 공지를 위한 검색·회귀 테스트를 추가했다. 사진은 실제 인용한 출처의 해시 기반 로컬 파일만 제공한다. 이미지 속 글자는 OCR/Vision으로 색인하지 않았다.

이 결과는 제한된 사례의 연동 검증이며 모든 질문의 정확도·응답시간·비용을 보장하지 않는다. CSS/JS/외부 폰트 등은 참조 목록으로 보관하며 웹사이트 전체를 오프라인 복제하지 않는다. 로그인·개인 마이페이지·주문·구매는 실행하지 않았다.

로컬 서버는 사용자 요청에 따라 127.0.0.1:8765에서 계속 실행 중이다. 임시 PostgreSQL 검증 컨테이너는 제거했다. AWS 리소스는 생성하지 않았으며 실제 RDS/S3 연동·예약 실행·Secrets Manager 운영 정책은 후속 검증 대상이다. 현재 S3 어댑터는 날짜별 식단 원문 보관만 지원하고, 포털·미디어 전체 S3 동기화는 추가 구현이 필요하다.

검증 환경은 Python3.14와 requirements.txt의 패키지 버전이다. 테스트에서 Starlette/httpx의 사용중단예정 경고1건이 있었으며 검사는 통과했다. Dockerfile의 Python3.12 앱 이미지 실행은 별도 검증 대상이다.

## 대화 DB 저장과 학식 질문 수정

질문·답변·출처·사진을 서버 DB에 저장하고 HttpOnly/Lax 식별 쿠키로 같은 브라우저의 대화만 복원하도록 변경했다. 이전 대화 목록에서 기록을 전환할 수 있고 새 대화는 기존 기록을 보존한다. 다른 소유자의 대화 접근, 중복 요청·충돌, API 오류 시 반쪽 저장, 이전 요청이 새 대화를 바꾸는 경우를 테스트했다. 실제 PostgreSQL에서도 영속 기록과 동시 저장·롤백을 확인했다. 과거 상대 날짜는 작성 당시 한국 날짜를 기준으로 해석하며 원문은 유지한다.

실제 브라우저에서 “내일 학시 뭐나와아”의 원문과 정상 AI 답변이 DB에 저장되고 새로고침 후 그대로 복원됨을 확인했다. 이후 “그럼 저녁은?”도 내일(11월 14일)의 창의인재원식당 고구마카레라이스 4,500원으로 안내하고 다른 식당의 미등록 상태를 구분했다. 일반 “학식”을 학생식당 하나로 고정하던 원인을 제거했고, 오타의 내부 정규화와 전체 식당 근거 보존, 확인된 빈 식단의 구체적인 출처 안내를 추가했다.

공개 소스 ZIP에는 실제 대화 DB를 그대로 넣지 않는다. 패키징 시 SQLite 사본에서 공개 지식 테이블 3개만 남기고 VACUUM하여 대화·세션의 삭제된 페이지까지 제외한다. 원본 운영 DB와 저장된 대화는 유지된다. 이 동작은 비공개 표식이 압축 DB에 없고 원본에 남아 있는 회귀 테스트로 확인했다.

대화 저장 수정 당시 전체 회귀는165개와하위검사21개를통과했다. 별도 실제브라우저에서 “내일 학식 뭐나와”도 새 대화로 질문해11월14일 창의인재원 중식·석식 각4,500원과 나머지 미등록 상태를 확인했다. 이전 대화 모달에서 오타 질문의 기록을 다시 열고 새로고침해도 질문2개·답변2개·공식출처가 그대로 복원됐다. 모바일390px에서도 대화목록 전환과 가로넘침없음을 확인했다.

## 친근한 답변·마크다운·자동 사진

친근한 해요체와 핵심부터 답하는 지침을 적용했다. GFM 제목·굵은 글씨·목록·표·코드·인용문을 렌더링하고 `[S1]`은 실제 공식 출처 링크로 연결한다. 저장된 이전 답변도 새로 렌더링한다. Marked18.2.0·DOMPurify3.4.17은 공식 배포본과 라이선스를 로컬에 고정했다. 실제 제품 스크립트와 jsdom을 사용한34개 DOM 검사는 모두 통과했다. 임의 HTML·스크립트·위험한 프로토콜·외부 이미지 제거, 인용 링크, 코드 보존, 이전 답변과 사용자 원문 처리를 포함하며 외부 자원 요청은0건이었다.

실제 답변 본문에서 인용한 자료에 검증된 사진이 있으면 최대6장을 자동 첨부한다. 모델이 임의로 넣은 사진 URL과 사용하지 않은 출처의 이미지는 제외한다. 기존 저장 답변도 인용된 출처의 사진을 복원한다. 공식 일별 페이지28곳을 다시 확인해 이미지 정보가 없던18개 날짜별 자료를 보완했다. 오류0건, 음식 사진48개를 확보했고 사진만 바뀌어 추가 임베딩은0개였다.

실제 웹에서 사진을 요청하지 않은 “학교 우체국 위치와 운영시간을 표로 간단히 알려줘”에 해요체 답변·굵은 글씨·GFM 표·공식 인용과 실제 사진이 함께 표시됐다. 사진의 naturalWidth는990이었다. 기존 DB 답변의 굵은 글씨와 공식 인용 링크 복원도 확인했다. 자모로 입력한 “ㄴㅐㅇㅣㄹ ㅎㅏㄱㅅㅣㄱ ㅁㅜㅓㄴㅏㅇㅗㅏ” 역시 내부에서 한글을 조합해11월14일의 실제 중식·석식과 다른 식사의 미등록 상태를 정상 안내했다. 사용자 원문은 그대로 유지했다.

390px 모바일에서 새로고침 후 같은 표·사진·대화가 복원됐고 문서 너비390px로 가로 넘침이 없었다. 원래 화면 크기로 되돌리고 검증 화면을 저장했다. 당시 전체 Python 회귀240개와하위검사21개가 통과했다. 저장된 과거 자모·NFD 상대 날짜도 원문을 유지한 채 작성일 기준으로 해석한다.

## 기간 해석·요청 시 갱신·정기 수집

11월14일 한국 시간 기준 실제 API 연동으로 다음을 확인했다.

- `내일 학식 알려줘`: 11월15일로 해석하고 창의인재원 중식 팽이소불고기·석식 돼지고기김치찌개 각4,500원, 나머지 미등록 상태를 공식 근거로 답했다. 4곳 캐시가 최신이라 추가 수집과 임베딩은0건이었다.
- `다음주 학식 알려줘`: 11월16~22일을 조회하고 날짜·식당별28개 근거로 실제 OpenAI 요약과 전체 기간 표를 제공했다. 7일 중 일부만 잘라 답하지 않았다.
- `2026년 11월28일부터30일까지 학생식당 점심 알려줘`: 미수집 범위3일을 질문 직후 실제 크롤링하고9개 청크를 임베딩했다. 공식 미등록으로 안내했고 다른 날짜 메뉴를 대신 쓰지 않았다.
- `그럼 저녁은?`: 같은 11월28~30일 범위를 이어받아 석식을 확인하고 최신 캐시3개를 재사용했다. 새 임베딩은0개였다.
- `2월30일 학식 알려줘`: 날짜 확인 안내를 반환하고 수집·모델 생성을 하지 않았다.
- 별도 임시 DB의 실제 공개11월15일 창의인재원 자료를3일 전 상태로 만들어 검증했다. 실제 재크롤1회와 임베딩3개가 완료됐고, 직후 재요청은 캐시를 재사용했다. 실행 중인 원본 DB의 시각을 조작하지 않았다.
- DB 재접속 시 질문·답변10개와 커스텀 날짜 범위·사용자 원문이 복원됐다.
- 실제 웹의 `다음주 월요일부터 수요일까지 학생식당 점심 알려줘. 사진도 있으면 보여줘`는 11월16~18일 메뉴·가격·전체 표와 공식 출처4개를 표시했다. 해당 날짜의 메뉴 사진은 없다고 구분하고 실제 시설 사진을 첨부했다. 이어지는 `같은 기간` 질문도 같은3일을 유지했다. 390px 모바일 새로고침 후 두 표의3개 날짜와 사진이 복원됐고 페이지 너비는390px였다.

내장 스케줄러는 실제 실행 중이며 시작 확인과60분 간격이 설정됐다. 11월14~27일56개 식당·날짜를 확인하고 오류0건, 전체 임베딩 준비 상태를 확인했다. 다음 시각과 마지막 처리 요약은 `/api/status`에서 확인한다. 서버가 켜져 있을 때 동작하는 단일 프로세스용 기능이며 서버 종료 중 예약 실행이나 AWS 배포는 검증한 범위에 포함하지 않는다.

추가 회귀는 날짜 별칭·모호한 표현·역순·윤년·연말·최대 범위, 범위별 임베딩 격리, 동시 수집 공유·실패 대기·갱신 실패 자료 제외, 혼합 사진/운영시간 요청의 전체 기간 보존, 수집 중 자정/월요일 변화와 같은 요청 재생을 포함한다. API의 `start_date/end_date`, 관리자 `refresh --start/--end`, `.env`의 기간 상한·정기 시작 오프셋·일수·간격을 각각 설정할 수 있다.

기간 조회 수정 당시 Python 회귀475개와하위검사21개, 실제 제품 스크립트의 DOM 검사34개가 모두 통과했다. 기존 Starlette/httpx 사용중단예정 경고1건이 있으며 기능 검사는 통과했다. 검증 후 원래 브라우저 크기를 복원하고 로컬 서버와 내장 정기 수집기는 실행 상태로 유지했다.

## 시설 개수와 전체 목록 질의 수정

일반 유사도0.30 검색과 상위8개 문서만으로 전체 시설 개수를 답하려던 문제를 수정했다. 개수·분류·목록 질문은 공식 `page:facility-directory`의 전체 `records`를 조회하고 시설 ID별로 집계한다. 같은 이름의7-eleven3개 지점을 이름으로 합치지 않으며, 공개 목록 내부의 `inactive`와 실제 영업 상태를 혼동해 제외하지 않는다. 공식 복합 분류와 이름 일부만 일치하는 하위업종을 구분한다.

11월14일 공식 전체 시설 페이지를 실제 다시 수집해48곳과7개 분류를 확인했다. 실제 API에서 편의점5곳, 세븐일레븐3곳, 학생복지관 편의점1곳, 카페/베이커리11곳을 각각 정확한 목록과 위치로 답했다. 전체 분류 질문도48곳·7분류를 유지했다. 실제 웹에 `학교에 편의점 몇개있어?`를 입력해5개 매장·위치의 표와 공식 출처가 즉시 표시되는 것을 확인하고 검증 화면을 저장했다.

목록 갱신은 공식 origin/path·목록 UI·비어 있지 않은 배열·양의 정수 ID·중복 ID·이름과 분류·표시 총수를 검증한 뒤 교체한다. 실패 시 기존 DB와 원문은 보존한다. 바뀐 카탈로그만 별도 범위로 임베딩해 다른 문서의 미처리 청크를 섞지 않는다. 시설 집계 회귀는 언어 변형·50개 초과 목록·브랜드·고유명·건물·층·후속 문맥·카탈로그 누락/만료/오류와 학식 요청을 가로채지 않는 경우를 포함한다.

이번 수정 후 기존 날짜별 학식 기능을 포함한 전체562개와하위검사21개가 통과했다. 로컬 서버를 최신 코드로 다시 실행했고 전체471개 청크가 색인된 준비 상태와 내장 정기 수집 실행을 확인했다.

## 상세 안내에만 있는 업종의 검색 누락 수정

`분식집 찾아줘`가 일반음식점의 상호와 일부 벡터 검색 결과에 의존해 이모네를 놓치는 문제를 수정했다. 전체 시설 ID를 상세 문서와 연결하고 상호·분류·설명·운영 공지에 업종 동의어를 적용한다. 같은 상호라도 ID가 다른 지점은 따로 확인하며, 복합 분류 문자열이나 부정 안내를 업종의 양성 근거로 삼지 않는다. 업종 근거와 상세 페이지의 시간·사진 출처도 구분한다.

실제 API와 웹에서 `학교에 분식집 찾아줘`에 이모네와33떡볶이&꼬마김밥이 함께 나오는 것을 확인했다. 공식48개 시설의 상세가 모두 유효해48/48완료였고, 개별 공식URL14/26의 출처2개·실제 사진3개(너비990/990/554px)가 표시됐다. 이모네의 근거는 운영 공지의 `이모네 분식점 입니다.`이며, 위치·월~토11:00~20:00·휴식14:30~16:00·일요일휴무도 같이 표시됐다. 실제 DOM에서 마지막 답변의 취소선 요소는0개였다. 검증 화면은 `분식집_전체검색_수정_확인.jpg`에 저장했다.

새 시설 상세 갱신기는 누락/유효시간 만료·5분 실패 대기·동시 요청 공유·개별 ID와origin/path 검증·선택시설 외 자료 보존·범위 임베딩을 검증했다. 업종 회귀는 상호에 단서가 없는 공지 전용 매장, 설명 전용 매장,20개 검색 결과 전체 보존, 부정·복수 업종과 미확인 상세 범위, 사진 및 출처 분리를 포함한다. 마크다운 DOM 검사는42개가 통과했으며 정상 요일·시각·ISO 범위만 정규화하고 코드·링크·URL·실제 취소선은 보존한다.

최종 전체 Python 회귀608개와하위검사21개가 통과했다. 기존 Starlette/httpx 사용중단예정 경고1건 외 실패는 없다. 실제 서버와 내장 정기 수집은 계속 실행 중이다.

## 학교 정보 전반의 종합 점검

특정 질문의 상호나 숫자를 추가하는 대신, 시설 대상을 해석하는 규칙·요청 항목·조건 필터·이전 대화의 지시 대상·근거 선택을 공통으로 수정했다. 위치·연락처·시간·건물번호·사진은 공식 상세 필드에서 조회하고, 공지·결제 정책·날짜별 식단은 해당 문서의 임베딩과 근거 기반 생성을 사용한다. 일반 정보의 문장 검색에는 본문 단어 일치를 함께 반영한다.

전체 시설 48곳 각각의 위치·운영시간·연락처·사진과 미확인 필드를 검사했다. 문자 안내에서 확인된 항목은 위치48곳·운영시간40곳·연락처23곳·사진48곳이며, 연락처25곳과 운영시간8곳은 다른 시설의 값으로 대신하지 않는지 검증했다. 이미지 속 글자를 읽은 결과는 아니다.

중간 종합 점검 155개 시나리오에서는 139개 통과·16개 실패가 있었다. 같은 저장 응답을 최종 형식 정규화 기준으로 다시 검사한 수치이며, 마크다운의 정상적인 `\~` 표기를 시간표 누락으로 오인한 두 건은 제외했다. 이후 다음 공통 원인을 수정했다.

- 여러 시설 이름 중 건물명이 들어간 이름이 다른 시설을 위치 필터로 탈락시키는 문제
- 위치·전화 등 여러 요청 항목 중 일부만 답하는 문제와 지점별 출처 누락
- 전화·시간·위치를 짧게 이어 물을 때 이전 시설을 잃는 문제, 목록·순서·나머지 대상의 해석
- 폐쇄 시간의 `까지`를 날짜 범위로 오인하는 문제와 `기숙사 식당`의 띄어쓰기
- 카페·편의점 등 여러 조건의 합집합/교집합, 이용 목적과 실제 판매 근거의 구분
- 현재 영업 여부와 공식 시간표, 토요일 적용 여부 및 24시간 조건을 혼동하는 문제
- 오래된 시설 문서가 과거 날짜라는 이유로 유효시간 제한을 우회하는 문제
- 공지의 목록·본문을 재확인하고 제거·실패한 공지를 현재 정책에서 제외하는 처리
- 일반 별칭이 미등록 고유명 내부에서 일치해 다른 은행·서점으로 대체하는 문제
- 위치·전화와 공지를 함께 물을 때 요청 항목이 누락되는 문제와 공지 제목 내부의 건물명·날짜를 질문 조건으로 오인하는 문제

실제 API 검사는 기존 사용자와 다른 새 쿠키·대화로 실행했다. 기존 사용자의 대화나 키를 읽지 않고 공개 지식 테이블만 정답 자료로 사용했다. 개수·시설 ID 집합·분류·위치·완전한 전화번호·시간과 요일 조건·미확인 안내·공식 출처·인용한 시설의 사진 연결을 자동 대조했다. 점검 결과는 이 사례와 수집된 공개 자료의 범위에 한정되며 모든 자연어 질문의 정확도를 의미하지 않는다.

재실행 명령은 다음과 같다. 결과 JSON은 새 QA 대화의 응답을 포함하므로 공유용 HTML은 별도의 허용 필드만 사용해 만든다.

```bash
python scripts/evaluate_school.py --database data/efoo.sqlite3 \
  --all-facilities --base-url http://127.0.0.1:8765 --output report.json
python scripts/render_school_report.py report.json --output school-audit.html
```

최종 결과는 **25개 질문 유형·159개 시나리오에서159개 통과·실패0개**다. 전체157개 실행 뒤 새 혼합 질문2개를 추가했으며, 공지 제목 해석 수정의 영향 범위인 기존 공지2개와 혼합2개를 다시 실제 API로 실행했다. 기존157개 사례 정의가 그대로인지 확인하고 최신 응답으로 합친159개 기록 전체를 강화한 동일 검사기로 재검사했다. 본문과 메타데이터의 개수가 다르거나 두 시설의 전화번호를 서로 바꿔 쓴 변형 응답이 실패하는 회귀도 포함한다.

최종 전체 Python 검사는877개와하위검사21개, 실제 제품 스크립트의 Markdown/사진 DOM 검사는42개가 통과했다. 실제 웹에서도 두 식당의 위치·전화, 첫 번째 시설의 토요일 문의, 창의인재원식당의 위치·미확인 연락처·결제 공지·사진을 확인했다. 보고서의 검색 필터와 사례별 답변·출처 표시도 브라우저에서 검수했다. [전체 점검 보고서](school-audit.html)는 공개 허용 필드만 담고 기존 사용자 대화·키·쿠키·세션 식별자는 포함하지 않는다.
